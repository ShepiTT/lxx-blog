# 第5期（2026-09-23）：把 AI 项目从想法推进到试点上线

## 1. 项目基线

<strong>知识讲解：</strong>基线是上线前的真实情况，用来比较项目上线后是否改善。没有基线，就难以证明价值。

<strong>企业案例：</strong>异常系统试点前记录异常数量、响应时间、信息不完整率和无法追踪比例。

<strong>参考做法：</strong>可以记录一个月的样本，再与试点后同口径数据对比。示例：平均响应从28分钟降到12分钟；这类数字必须由现场测量得到。

<strong>可选练习：</strong>为什么只统计注册人数不够？

<strong>参考答案：</strong>人数只表示有人登录，不能证明处理时间、差错或成本改善。

## 2. MVP 最小可行产品

<strong>知识讲解：</strong>MVP用最小的一组功能验证核心问题能否解决，不是随便做个简陋版本。

<strong>企业案例：</strong>异常系统第一期可做上报、图片、分派、状态跟踪和基本统计。

<strong>参考做法：</strong>先打通异常处理闭环，AI分析、语音录入和自动报告放到后续阶段评估。

<strong>可选练习：</strong>知识库 MVP 应具备哪些能力？

<strong>参考答案：</strong>上传资料、检索、带来源回答、无依据时说明、基础权限控制。

## 3. PRD 需求文档

<strong>知识讲解：</strong>PRD让业务、开发、测试和管理人员对目标、范围和规则有同一理解。

**企业案例：**“支持异常上传”太模糊，还要说明谁能传、必填字段、图片限制、通知对象和撤回规则。

<strong>参考做法：</strong>PRD包含背景、目标、用户、流程、功能、规则、权限、异常处理、验收标准、非目标和风险。

<strong>可选练习：</strong>PRD是否应一开始就指定大模型品牌？

<strong>参考答案：</strong>通常先定义能力、质量、成本和安全要求，再在技术方案中根据评测选型。

## 4. API 契约

<strong>知识讲解：</strong>API 契约约定地址、方法、字段、返回值、错误、权限和版本，让前后端及其他系统按同一规范集成。

<strong>企业案例：</strong>POST /api/v1/production-abnormalities 可接收批次号、异常类型和描述，并返回记录编号与状态。

<strong>参考做法：</strong>批次不存在时返回明确错误码和说明，不要只回“系统错误”。接口版本可避免改动后旧调用方立即失效。

<strong>可选练习：</strong>新增一条质检记录通常用 GET 还是 POST？

<strong>参考答案：</strong>通常用 POST；GET 用于读取，不应承担创建记录的副作用。

## 5. 开发、测试与生产环境

<strong>知识讲解：</strong>开发环境用于实现和调试，测试环境用于验证，生产环境供正式业务使用。未经验证的代码和虚假测试数据不应直接进入生产。

<strong>企业案例：</strong>开发人员若直接连接正式库存数据库，测试可能改变真实库存。

<strong>参考做法：</strong>开发 → 自动检查 → 测试环境验收 → 备份 → 发布生产 → 上线观察；准备回退方式，测试数据应脱敏或模拟。

<strong>可选练习：</strong>测试环境能否直接复制全部生产数据？

<strong>参考答案：</strong>不应未经处理复制。涉及员工、客户、价格等敏感数据时应脱敏或使用模拟数据。

## 6. AI 模型选择

<strong>知识讲解：</strong>选择模型需要综合质量、速度、成本、数据要求、稳定性和部署方式，并用同一评估集比较。

<strong>企业案例：</strong>制度问答重视检索和引用；固定字段提取可尝试更轻量的模型。

<strong>参考做法：</strong>简单任务先用成本较低的方案，复杂任务再升级模型；敏感数据按公司安全要求处理；模型不可用时保留人工路径；高风险输出需确认。

<strong>可选练习：</strong>所有任务都用能力最强的模型是否最合适？

<strong>参考答案：</strong>不一定。简单任务可能因此增加费用和等待，却没有明显业务收益。
